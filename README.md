# AI-Powered Resume Fit Analyzer

A web app that compares a PDF resume with a job description and tells a job seeker, before they apply: their fit
score, which skills they are missing, what to learn (with free links), and whether the resume format will survive ATS
screening.

The full specification is in [docs/PROJECT_SPEC.pdf](docs/PROJECT_SPEC.pdf). The architecture diagram is in
[docs/architecture.jpg](docs/architecture.jpg).

## Run the backend

PowerShell (Windows):

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
python -m spacy download en_core_web_sm
python -c "import nltk; nltk.download('stopwords')"
python scripts/seed_db.py
uvicorn app.main:app --reload --port 8000
```

macOS / Linux: same steps, but activate with `source .venv/bin/activate`.

Installing the CPU-only PyTorch build first keeps the download much smaller (no GPU is needed). The first start
downloads the embedding model (`all-MiniLM-L6-v2`, about 90 MB) and can take a minute; after that it is cached and
`/api/health` reports `"model_loaded": true`. The spaCy model
and NLTK stopwords downloads are one-time steps. `seed_db.py` builds `data/app.db` from `data/skills_seed.json`; run it
again whenever the seed file changes (it is safe to rerun).

### Skills and learning links

`backend/data/skills_seed.json` lists every skill the app can detect, with aliases and free learning links. After
editing it, check that every link still works (needs internet; exits with an error if any link fails):

```powershell
python scripts/check_links.py
python scripts/seed_db.py
```

Run the link check before every release. If a link fails, replace it or remove it. Never add a link you have not
checked.

Check it works: open http://localhost:8000/api/health. You should see
`{"status":"ok","model_loaded":false,"version":"1.0.0"}`. Interactive API docs are at http://localhost:8000/docs.

Run the tests (from `backend/`, with the venv active):

```powershell
pytest
```

Add `-s` to see the Objective 1 report (how many of the 10 fixture PDFs extract correctly).

### Sample resumes and test PDFs

`backend/tests/fixtures/` holds the parser test PDFs. All people in them are fictional. Two of them are sample
resumes you can use to try the app:

- `sample_resume_backend.pdf` (single column, backend developer)
- `sample_resume_frontend.pdf` (two columns, frontend developer)

For the ATS check, `ats_good_resume.pdf` passes all 10 checks and `ats_bad_resume.pdf` (two columns, a table, icons
and star ratings) shows the warnings and fixes; use it for step 3 of the demo script.

To rebuild the fixtures (Windows, uses fonts from `C:\Windows\Fonts`): `python tests/fixtures/make_fixtures.py`.

### API

| Endpoint | What it does |
| --- | --- |
| `GET /api/health` | `{"status": "ok", "model_loaded": ..., "version": "1.0.0"}` |
| `GET /api/evaluation` | contents of `eval/report.json`, or 404 `no_report` |
| `POST /api/analyze` | multipart form: `resume` (PDF, max 5 MB), `job_description` (50-10,000 characters), optional `method` (`embeddings`, `tfidf` or `both`) |

Try it from `backend/` with the sample files:

```powershell
curl.exe -F "resume=@tests/fixtures/sample_resume_backend.pdf" -F "job_description=<eval/jds/j01.txt" http://localhost:8000/api/analyze
```

Errors always look like `{"error": {"code": "...", "message": "..."}}` with the codes from the spec
(`invalid_file_type`, `file_too_large`, `jd_too_short`, `jd_too_long`, `unreadable_pdf`, `too_many_pages`,
`internal_error`).

### Evaluation dataset

`backend/eval/` holds the hand-labelled pairs used to compare TF-IDF and sentence embeddings:

- `resumes/*.pdf` and `jds/*.txt` are fictional documents generated by `python eval/make_dataset.py`. They are also
  the reference corpus the TF-IDF vectorizer is fitted on.
- `pairs.json` lists which resume goes with which job description. **The `label` field must be filled in by the team**
  (`good`, `average` or `poor`). Two members should label independently, then agree on disagreements.
- Rerunning `make_dataset.py` keeps labels that are already filled in.
- Optionally add `label_a` and `label_b` (each labeller's own answer) next to the agreed `label`; the report then
  counts how many pairs the two labellers disagreed on.

Run the evaluation (from `backend/`) after labelling or changing a matcher:

```powershell
python eval/evaluate.py
```

It scores every pair with each method, compares the predicted label (from the `LABEL_GOOD_MIN` / `LABEL_AVG_MIN`
thresholds) with the hand label, and writes `eval/report.json`: agreement %, confusion matrix, Spearman correlation
and mean score per label. `GET /api/evaluation` serves that file to the Evaluation page. Pairs without a label are
scored but left out of the metrics, so the report never shows agreement figures for unlabelled data.

Honesty rule (Section 12): report results with the default thresholds first. If you tune thresholds or ceilings on
these same pairs, say so; the report lists any overridden settings automatically.

## How the fit score is calculated

The main score ([backend/app/services/scoring.py](backend/app/services/scoring.py)) adds up points from five
categories. Each category earns between 0% and 100% of its points, so the total can never pass 100. The response's
`breakdown` lists every category's points, and they add up to `fit.score`.

| Category | Points | Rule |
| --- | --- | --- |
| Required technical skills | 35 | JD skills the resume has anywhere, weighted required 3 / no cue 2 / preferred 1. Exact name or alias = full credit, a skill built on it = 0.75, an alternative = 0.40. Repeats and skills the JD doesn't ask for add nothing. |
| Experience and project evidence | 25 | The same skills, but only when an Experience or Projects bullet shows them. A skill that is only listed gets nothing here. |
| Job responsibilities | 20 | Each JD duty against its most similar resume bullet (sentence embeddings, or shared words without the model). |
| Education and qualifications | 10 | Degree level, years of experience (from dated roles, and only roles involving the skills named) and certifications: met 1, in progress 0.5, not met or not stated 0. |
| Resume completeness and readability | 10 | The ATS check score. |

If the JD gives a category nothing to measure (for example, no degree or years), that category is left out. Its
points go to the other job-match categories, and readability always stays at 10. The TF-IDF and embedding scores
are still computed and shown, for the method comparison and Objectives 2–3.

## Environment variables (backend)

All of these are optional. Defaults are in [backend/app/config.py](backend/app/config.py).

| Name | Default | Meaning |
| --- | --- | --- |
| `MAX_UPLOAD_MB` | 5 | Max PDF size |
| `MAX_PDF_PAGES` | 5 | Reject longer PDFs |
| `MIN_JD_CHARS` / `MAX_JD_CHARS` | 50 / 10000 | Job description length limits |
| `EMBEDDING_MODEL` | sentence-transformers/all-MiniLM-L6-v2 | Embedding model |
| `PRIMARY_METHOD` | weighted | Main fit score: `weighted` (see below), `tfidf` or `embeddings` |
| `WEIGHT_SKILLS` / `WEIGHT_EVIDENCE` / `WEIGHT_RESPONSIBILITIES` / `WEIGHT_QUALIFICATIONS` / `WEIGHT_READABILITY` | 35 / 25 / 20 / 10 / 10 | Points per category of the weighted score |
| `IMPORTANCE_WEIGHT_HIGH` / `_MEDIUM` / `_LOW` | 3 / 2 / 1 | How much a JD skill counts: required / no cue / preferred |
| `IMPLIED_SKILL_CREDIT` / `RELATED_SKILL_CREDIT` | 0.75 / 0.40 | Partial credit for a skill built on the one asked for (Django → Python) / an alternative (MySQL → PostgreSQL) |
| `RESP_SIM_FLOOR` / `RESP_SIM_FULL` | 0.30 / 0.65 | Similarity of a JD duty to a resume bullet that earns 0 / full credit |
| `TFIDF_CEILING` | 0.60 | Raw TF-IDF cosine mapped to 100% |
| `EMBED_CEILING` | 0.80 | Same, for embeddings |
| `LABEL_GOOD_MIN` / `LABEL_AVG_MIN` | 65 / 40 | Good / Average / Low fit thresholds |
| `CHUNK_MAX_WORDS` / `CHUNK_MIN_WORDS` / `CHUNK_OVERLAP_SENTENCES` | 30 / 5 / 1 | How texts are split into chunks for embeddings (sentence-level) |
| `ALLOWED_ORIGINS` | http://localhost:5173 | CORS origins, comma-separated |
| `DB_PATH` | data/app.db | SQLite file (relative to `backend/`) |
| `EVAL_REPORT_PATH` | eval/report.json | Report served by `GET /api/evaluation` (relative to `backend/`) |
| `LAZY_MODEL_LOAD` | false | `true` loads the embedding model on the first request instead of at startup |

## Deploy (free tier)

The backend goes to Render and the frontend to Vercel, both from the GitHub repository (Section 15).

### 1. Push to GitHub

Create an empty repository on GitHub, then from the project folder:

```powershell
git remote add origin https://github.com/<your-account>/resume-fit-analyzer.git
git push -u origin main
```

The `tests` workflow in `.github/workflows/tests.yml` then runs the backend and frontend tests on every push.

### 2. Backend on Render

1. In Render, choose **New > Blueprint** and pick the repository. Render reads [render.yaml](render.yaml).
2. When asked for `ALLOWED_ORIGINS`, enter a placeholder for now (for example `http://localhost:5173`); you will
   change it in step 4.
3. Wait for the first build. It installs CPU-only PyTorch, downloads the spaCy model, NLTK stopwords and the
   embedding model, and seeds the database, so it takes several minutes.
4. Open `https://<your-service>.onrender.com/api/health`. You should see `"model_loaded": true`.

If the service crashes with "out of memory" (the free plan has about 512 MB), set the environment variable
`LAZY_MODEL_LOAD` to `true` in the Render dashboard and redeploy. If it still does not fit, stop and talk to the
team: the remaining options (an ONNX-based embedding library, or Hugging Face Spaces) change the tech stack shown on
the slides.

### 3. Frontend on Vercel

1. In Vercel, choose **Add New > Project**, import the repository and set **Root Directory** to `frontend`.
   Vercel detects Vite; [frontend/vercel.json](frontend/vercel.json) sets the build and makes page refreshes work on
   every route.
2. Add the environment variable `VITE_API_BASE_URL` = `https://<your-service>.onrender.com` (no trailing slash).
3. Deploy, and note the URL, for example `https://resume-fit-analyzer.vercel.app`.

### 4. Connect them

In Render, set `ALLOWED_ORIGINS` to the Vercel URL (no trailing slash) and save; Render redeploys. Then open the
Vercel URL on a phone and run one analysis with `backend/tests/fixtures/sample_resume_backend.pdf`.

### Before a demo

Free Render instances sleep after about 15 minutes without traffic. Open `/api/health` on the Render URL a minute
before the demo so the first analysis is fast. The full demo steps are in
[docs/demo-script.md](docs/demo-script.md).

## Privacy

Uploaded resumes and job descriptions are processed in memory and never stored or logged. The fit score is an
estimate to help applicants improve; it must not be used to make hiring decisions about people.
